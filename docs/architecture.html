FIG 1

System architecture

A single Flask application in six layers. Both audiences use the same app; role guards decide which blueprint they can reach. All AI goes through LangChain to Hugging Face models by default; moving to a paid provider is a .env change, and the app keeps working in rules mode without any model.

FIG 2

AI layer (LangChain)

Every model call is a LangChain chain: a prompt template, a chat model and a parser. One factory builds the model from LLM_PROVIDER and LLM_MODEL, so free Hugging Face models and paid models run the same chains. Free models get JSON instructions, tolerant parsing and one repair attempt; paid models use native structured output.

FIG 3

Job description lifecycle

Requirement 1: the AI agent drafts, a human reviews and approves. Job.status moves through four states; only approved jobs appear on the careers site.

FIG 4

Resume screening pipeline

Requirement 2: every application is scored the moment it is submitted. A deterministic keyword score and an AI score are blended, so no single model judgement decides a shortlist.

FIG 5

Data model

Five tables in models.py. Job holds both the requisition inputs and the approved JD; Application holds the resume text and every screening output so the ranked pipeline is a single query.

Deployment options

Same code in every environment; only environment variables and storage change.

Local / pilot

python app.py
  • Flask dev server on port 5000
  • SQLite file in instance/
  • Resumes on local disk
  • HF token for the API, or huggingface_local to run a free model on the machine (requirements-local.txt)
pip install -r requirements.txt
flask --app app ai-check
flask --app app seed-demo
python app.py

Docker

Dockerfile · gunicorn, 2 workers
  • python:3.12-slim image
  • Mount /app/instance as a volume for DB and resumes
  • Settings from --env-file .env
docker build -t talentflow .
docker run -p 8000:8000 --env-file .env \
  -v $PWD/instance:/app/instance talentflow

Render / PaaS

Procfile · managed PostgreSQL
  • Set DATABASE_URL to Postgres; add psycopg2-binary
  • Persistent disk for resumes, or swap store_resume() to S3 / Azure Blob
  • SECRET_KEY, HUGGINGFACEHUB_API_TOKEN, LANGSMITH_API_KEY, admin credentials as env vars
TABLE 3

Security and governance controls

Authentication
Werkzeug password hashing, Flask-Login sessions, inactive users blocked at login.
Authorisation
hr_required and candidate_required guards on every view; resumes served only to HR or their owner; safe redirect targets.
Forms
CSRF token on every POST via Flask-WTF, including the markdown preview call.
Uploads
PDF or DOCX only, 5 MB cap (413 handler), stored under random UUID names outside /static.
AI output
JD markdown rendered through nh3 with a tag allow-list, never as raw HTML.
AI input
Resume wrapped as untrusted data; the prompt tells the model to ignore embedded instructions and protected attributes.
Governance
Human approval of every JD, optional maker-checker, JDRevision history and ActivityLog for every action.
